# Evaluation 模块

面试考点: Agent评估体系、三维看板、失败归因

## 核心实现

### AgentEvaluator (`agent_evaluator.py`)

**三维评估体系**:

| 维度 | 指标 | 说明 |
|------|------|------|
| **效能** | 任务完成率、平均步数、Token成本 | 关注效率和成本 |
| **质量** | 准确率、用户满意度、一次解决率 | 关注结果质量 |
| **鲁棒性** | 异常处理成功率、自修复率、MTBF | 关注稳定性 |

**失败归因分类**:
- `intent_error`: 意图理解错误
- `planning_error`: 规划错误
- `tool_error`: 工具调用错误
- `memory_error`: 记忆错误

**运行**:
```bash
python evaluation/agent_evaluator.py
```

## 面试Q&A

**Q: 如何量化评估一个上线的Agent？**

A: 三维看板：
1. **效能**: 任务完成率、平均完成步数、Token成本
2. **质量**: 准确率（人工抽检）、用户满意度、一次解决率
3. **鲁棒性**: 异常处理成功率、自修复触发率、平均无故障运行时间

关键是每次失败都要找到具体原因，归到对应模块（意图/规划/工具/记忆），放进优化队列驱动迭代。
